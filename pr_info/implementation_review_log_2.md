## Round 4 — 2026-09-04

**Findings**

1. `src/mcp_tools_py/main.py:215` (medium-low) — the startup error prints to stdout, which is the stdio protocol channel; clients capture stderr, so the one message `README.md:185` points users at lands on the stream they cannot see. It is also never logged.
2. `src/mcp_tools_py/main.py:203-216` (low) — the `try` wraps all of `create_server`, so an unrelated `FileNotFoundError` from deeper inside loses its traceback.
3. `tests/test_main_args.py:73-96` (low) — patching `create_server` with `side_effect=FileNotFoundError` makes the test assert only that the `except` clause exists, and the `--python-executable` argument in `argv` is never exercised.
4. `README.md:157-161` (trivial) — the POSIX variant is a bare key/value fragment inside a ```json fence and does not parse.
5. `src/mcp_tools_py/main.py:52` (trivial) — round 3 made the epilog absolute but POSIX-only, on a Windows-primary repo.
6. `README.md:137` (low) — bare-name PATH resolution is advertised without noting that a non-venv interpreter leaves the five console-script tools unavailable.

No critical or high findings.

**Decisions**

All six accepted; each is a few lines, in text or code this branch introduced. 1 and 2 were fixed together rather than by narrowing the `try`.

**Changes**

The `except FileNotFoundError` now logs with `exc_info=True` before printing to `sys.stderr`, so the friendly exit survives for the interpreter case while anything else stays diagnosable; the sibling `--project-dir` error moved to stderr for consistency. The test dropped its `create_server` patch, so real resolution raises from the non-existent path — `FastMCP` is constructed before `_resolve_python_executable`, so the unpatched path stops short of the five registrars, matching what the rest of the suite already does. The epilog shows both platforms and its literal became a raw string, without which the Windows path's `\t` would render as a tab in `--help`. The POSIX fence became `text`, and one clause was added to the troubleshooting bullet.

One assertion was deliberately dropped: stdout could not be asserted clean, because `create_server` carries `@log_function_call` and, with `setup_logging` patched out, structlog's default `PrintLogger` renders a traceback to stdout whose text contains the searched substring. That is a harness artifact — `mcp_coder_utils/log_utils.py:263` builds the real console handler as a bare `StreamHandler()`, documented as stderr precisely so stdio MCP servers never write to stdout.

Files: `src/mcp_tools_py/main.py`, `README.md`, `tests/test_main_args.py`.

Checks: pylint, ruff, mypy clean, pytest 648 passed / 1 skipped.
